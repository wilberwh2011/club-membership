# Public functions

Callable without a session. Types: [api-types.ts](api-types.ts).

## `submitRegistration(sessionToken | null, request) → Result<RegistrationOutcome>`

One function for both channels, so the form, fields and rules are identical (FR-011, US3 AS1).

**Who**: anyone without a session (self-registration); with a session, only callers holding `member.register`
(EC member, Admin). A session without that capability (treasurer only) → `FORBIDDEN` (US3 AS4).

**Input**: `RegistrationRequest` — `input` (FR-002 fields except Note and system fields), `submissionId`,
`formToken`, `honeypot`, `language`.

**Processing order**:

1. Public caller only: `honeypot` non-empty → return `{ok: true, data: {kind: 'received'}}` (no member number), store nothing (R5).
2. Public caller only: verify `formToken` HMAC and age 3 s…24 h → else `FORM_EXPIRED`.
3. Public caller only: rate-limit window over threshold → `RATE_LIMITED`.
4. Validate (pure domain): at least one name; `membershipType`; email/phone format; birthday month/day;
   lengths; `privacyAcknowledged = true` → else `VALIDATION_FAILED` with every field error at once (US1 AS8).
5. Acquire script lock (`BUSY` on timeout).
6. If `submission:<submissionId>` or `content:<hash>` exists in cache → return the stored result, i.e. the same
   member number (FR-009, FR-010).
7. Duplicate rule (FR-012) against `email_key` / `phone_key` of existing Members rows:
   - public caller → `ALREADY_REGISTERED` (no indication of which value, no member number, no record data; FR-009);
   - signed-in caller → `DUPLICATE_EMAIL` or `DUPLICATE_PHONE` with `memberNumber` (email checked first).
   A name match alone never blocks (US1 AS7, SC-005).
8. Assign member number (R4), set `registrationDate` = `privacyAckDate` = today (Club time zone),
   `registrationEvent` = trimmed value or `N/A`, `note` = empty, `version` = 1.
9. Write Members row + ChangeHistory (`member_created`, `actor_kind` = `self_registration` or `club_user` with
   `actor_user_id`) + ChangeValues (all submitted fields); commit counter; flush. Failure → roll back → `SAVE_FAILED`.
10. Cache the result under `submission:` and `content:` keys (10 min); release lock.

**Output**: both channels → `{kind: 'created', memberNumber}`: the new member number and nothing else from the
record (FR-009). The duplicate-registration response (`ALREADY_REGISTERED`) returns no member data.

**Errors**: `VALIDATION_FAILED`, `ALREADY_REGISTERED`, `DUPLICATE_EMAIL`, `DUPLICATE_PHONE`, `FORBIDDEN`,
`FORM_EXPIRED`, `RATE_LIMITED`, `BUSY`, `SAVE_FAILED`, `INTERNAL`.

**Note on disclosure**: `ALREADY_REGISTERED` lets a visitor learn that *some* record uses an email or phone they
typed. The spec requires this message (FR-009, US1 AS6); the global rate limit bounds probing.

**Acceptance coverage**: US1 AS1–AS8, US3 AS1–AS4, edge cases "submits twice", "former member", "deleted records".

**Tests**: US1 AS1 asserts the public success result is `{kind: 'created', memberNumber}` with no other record field;
the "submits twice" test asserts both submissions return the same `memberNumber` and one record exists; US1 AS6
asserts `ALREADY_REGISTERED` carries no `memberNumber` or record data.

## `beginSignIn(clientNonce) → Result<{authUrl}>`

**Who**: anyone. **Input**: `clientNonce` (≥ 32 random chars generated by the client and kept in `sessionStorage`).
**Processing**: create random `state`, store `oauthstate:<state>` → `{clientNonce}` (10 min, single use), build Google
authorization URL: `client_id`, `redirect_uri = WEB_APP_URL`, `response_type=code`, `scope=openid email`,
`prompt=select_account`, `state`. **Errors**: `VALIDATION_FAILED` (bad nonce), `INTERNAL`.
**FRs**: FR-023 (sign-in page), research R1.
